# UI hydration render-path audit

Audited for the renderer commit lifecycle change, October 2026. This covers package-owned rendering; hosts must still
supply matching JSX, config, translations, and dehydrated data.

| Checked paths                                                                                                                                | Finding and handling                                                                                                                                                                                                                                                                                     |
| -------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `index.ts`, browser/string renderers, `AppContext`, `Instance`                                                                               | Added explicit deferred commit signal; browser and declarative renderers use it. Captured stable Redux `serverState` before `afterCreate`. Removed the extra render after `hydrateRoot`; reuse browser roots. Legacy synchronous custom renderers complete on return.                                    |
| Browser `views` plugin, `afterRender` plugins                                                                                                | Views, local storage, feature deep links and persisted geolocation now run after the reported commit. Fixed resize condition so both added and removed breakpoints wait for `hasRendered`; latest pre-commit width is retained.                                                                          |
| `LinkShare`, geolocation sort control                                                                                                        | Browser capability reads could change initial markup. Native share now waits for hydration. Both geolocation sort controls keep their capability branches inside initially closed popovers, which only open on interaction.                                                                              |
| `NativeDialog`, `PopoverDialog`, react-modal wrapper                                                                                         | Native inline dialogs now render on the server; native portals are omitted on server and initial hydration, then mounted. React Aria overlay containers already defer portals during SSR; react-modal mounts its portal after mount.                                                                     |
| `BottomSheet`, snap helper                                                                                                                   | Default snaps and host factories depended on browser height during state initialization. Initial snaps now use explicit arrays or a fixed 800px reference viewport; factories and actual viewport sizing run in the existing effect.                                                                     |
| i18n helper, `DistanceLabel`, tag sorting, measurement overlay                                                                               | Removed document-derived implicit language. Default `de` and explicit host language work on both sides. Distance and tag sorting already use that locale; measurement formatting now does too, instead of runtime-default `Intl` formatters. Hosts must provide the same language/catalogs.              |
| `TimeFilter`                                                                                                                                 | Initial input formatter assumed Date objects and local process timezone. It now accepts JSON ISO strings and uses UTC date fields. Flatpickr runs only in an effect; current-date selection/parsing happens on interaction.                                                                              |
| `useMapsightIcon`, `MapsightIcon`                                                                                                            | Warm runtime cache could change the initial hook output. Use a deterministic pending placeholder and read cache in the effect. Static/composable image sources are deterministic from ID and configured image base URL.                                                                                  |
| Map/map wrapper, synced interlay, tooltip positioning, sticky headers, search/query inputs, selection scrolling, focus/inert hooks, overlays | DOM measurements, scroll positions, listeners, OpenLayers mounting and browser navigation/clipboard calls occur in effects or event handlers. Initial render derives from props/store or deterministic empty refs/state. No changes needed.                                                              |
| IDs, clocks and randomness throughout UI components/hooks/helpers                                                                            | Dynamic IDs use React/React Aria `useId`; no random/UUID/counter-generated render IDs found. TimeFilter's fixed IDs remain deterministic (multiple-instance accessibility is a separate concern). `Date.now()` only tracks pointer/selection scroll events; no current-time or random render text found. |
| Starters, showcase, Vite host embed, SSR sidecar                                                                                             | CMS starter uses the default embed renderer. Next/SPA/showcase use `Instance`, so need no renderer callback changes. The sidecar transports host-rendered HTML/state; its host renderer must follow the contract. The Vite plugin builds assets and does not own hydration.                              |

Regression tests cover real `renderToString` → `hydrateRoot` app hydration with desktop HTML and mobile breakpoint
updates, node/focus preservation, an immediate live-store update before hydration, renderer callbacks/return values, late Suspense hydration, root reuse,
StrictMode replay, declarative Instance updates, DOM-free SSR, capability differences, viewport factories, warm icon
cache, locale defaults and serialized dates. Starter E2E checks Next hydration at mobile and desktop widths. Hydration tests assert both recoverable errors and console diagnostics.
