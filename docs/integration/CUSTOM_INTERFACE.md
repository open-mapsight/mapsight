# Bring your own interface

Use the Mapsight map and state inside an interface you build yourself: `Instance` and `Map` from `@mapsight/ui`,
without `App`, without the Mapsight chrome and without its SCSS. Everything the map needs beyond the canvas — buttons,
panels, lists, attribution, styling — is yours.

---

## When this path fits

| Path                                | You get                                                     | You bring                      |
| ----------------------------------- | ----------------------------------------------------------- | ------------------------------ |
| `create()` or `Instance` + `App`    | Map, list, filters, overlays, layer switcher, default theme | Config, style function, SCSS   |
| Presets (`simpleMap` and others)    | The same chrome, preconfigured for CMS embeds               | Container, inline options      |
| **`Instance` + `Map` (this guide)** | Declarative map runtime, selection, feature sources         | All visible chrome and styling |

Choose this path when a design system or product shell dictates the interface and only the map should come from
Mapsight. If you want the ready-made chrome, start with [Getting started](../getting-started.md) or
[React SPA](REACT_SPA.md).

`Instance` and `Map` give you a Redux store with the map controller (layers and sources from config, view, pan and
zoom, selection by click or hover, draw order, base-layer handling), feature sources with loading and refresh, feature
selections (`select`, `highlight`, `preselect`), and actions and selectors to drive and read all of it from your own
React components. You bring every visible control and panel, the attribution line, and the CSS for the few classes
`Map` renders (see [CSS without the Mapsight stylesheets](#css-without-the-mapsight-stylesheets)).

---

## Smallest working example

### Packages

```bash
pnpm add @mapsight/ui @mapsight/core @mapsight/lib-ol ol react react-dom
pnpm add -D @mapsight/vector-style-compiler
```

`@mapsight/ui` provides `Instance`, `Map`, the config helpers and the plugins; `react` and `react-dom` are its peers.
You import `@mapsight/core` actions and selectors directly. Generated style modules import `@mapsight/lib-ol` and
`ol/style/*`, and `ol` is a peer of `@mapsight/lib-ol`. `@mapsight/traffic-style` is optional: it is only needed for its
precompiled style and icon set.

Style modules generated by a compiler release that emits the small path and replace helpers inline no longer import
`@mapsight/lib-js`. Regenerate older style modules before removing a direct `@mapsight/lib-js` dependency.

### Style function

Vector features need a compiled style function. Points need `image-type`; the selector name matches the layer's
`style`, and `state` is set by feature selections.

```css
/* src/styles/places.css */
#places {
	image-type: circle;
	circle-radius: 6;
	circle-fill-color: #0071ad;
	circle-stroke-color: #ffffff;
	circle-stroke-width: 2;
}

#places[state="highlight"],
#places[state="select"] {
	circle-radius: 9;
	circle-fill-color: #e4572e;
}
```

Compile it with `vector-style-compiler src/styles/places.css --output src/generated --name places` (add it as an npm
script that runs before `dev` and `build`). This writes `src/generated/places.js`, the style function, and
`places.css`. In TypeScript, enable `allowJs` or declare the module, and exclude the generated file from type checking.
Compiler details: [vector-style-compiler README](../../packages/vector-style-compiler/README.md).

### Config and plugins

```ts
// src/mapsight.ts
import {fromLonLat} from "ol/proj";

import {features, map} from "@mapsight/ui/config";
import {xhrJson} from "@mapsight/ui/config/feature/sources";
import {interactiveFeatures, osm} from "@mapsight/ui/config/map/layers";
import createLangPlugin from "@mapsight/ui/plugins/common/lang";
import createOlProxyPlugin from "@mapsight/ui/plugins/common/ol-proxy";
import type {CreateOptions} from "@mapsight/ui/types";

const center = fromLonLat([10.5, 52.2]);

export const baseMapsightConfig = {
	...map(
		{
			base: osm("https://tile.example.org/{z}/{x}/{y}.png", true, {
				title: "Base map",
				attribution: "© Example contributors",
				isBaseLayer: true,
			}),
			places: interactiveFeatures(
				"places",
				true,
				{title: "Places"},
				"places",
			),
		},
		{center, zoom: 12, minZoom: 3, maxZoom: 18},
	),
	...features({
		places: xhrJson("https://example.org/data/places.geojson"),
	}),
};

export const createOptions: CreateOptions = {
	lang: "en",
	plugins: [
		["lang", createLangPlugin()],
		["olProxy", createOlProxyPlugin()],
	],
};
```

`map()` supplies the `interactions` (pan, zoom, keyboard) and `featureInteractions` (click and hover selection) that
the map controller reads from its state, so a hand-written `map` slice needs these keys as well. `features()` supplies
the `select`, `highlight` and `preselect` selections. A visible layer asks its feature source for data once OpenLayers
requests features, so the initial load needs no extra code.

### Component

```tsx
// src/city-map.tsx
import Instance from "@mapsight/ui/components/instance";
import MapsightMap from "@mapsight/ui/components/map";

import styleFunction from "./generated/places.js";
import {baseMapsightConfig, createOptions} from "./mapsight.ts";

export function CityMap() {
	return (
		<Instance
			baseMapsightConfig={baseMapsightConfig}
			createOptions={createOptions}
			styleFunction={styleFunction}
		>
			<div className="city-map">
				<MapsightMap mapTitle="Places in Example City" />
			</div>
		</Instance>
	);
}
```

- Keep `baseMapsightConfig`, `createOptions` and `styleFunction` stable (module constants or memoized). `Instance`
  creates the store in `useMemo` keyed by these three props; new object identities on every render create a new store.
- Everything inside `Instance` can use `react-redux` hooks (`useStore`, `useDispatch`, `useSelector`) and the hooks
  described below.
- `Map` fills its parent (`width` and `height` 100%). Give the parent a definite height.
- Do not pass `className` to `Map`: it replaces `ms3-map-target`. Wrap `Map` in your own element instead.

## Plugins

`createOptions.plugins` is empty by default: `Instance` registers nothing for you. A plugin is a `[name, plugin]`
pair; a later entry with the same name replaces an earlier one and `null` removes it. For a map, two are the minimum:

| Plugin    | Does                                                                          | Without it                                                                                                                                                                |
| --------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lang`    | Applies `createOptions.lang` to the UI strings before render                  | `lang` is ignored and strings stay German, including the map's accessible name, hidden text and keyboard help                                                             |
| `olProxy` | Registers the OpenLayers definitions (layers, sources, interactions, formats) | The console logs `ol-proxy: Cannot update proxy object. Dependency unknown/not injected: TileLayer` (and the interaction types); the map has no layers and no pan or zoom |

Registration is global: definitions and the language live in module state and are shared by every `Instance` on the
page.

`createDefaultPlugins` from `@mapsight/ui/plugins/browser-defaults` returns the full set in order
(`@mapsight/ui/plugins/server-defaults` is the server variant). Besides `lang` and `olProxy` it contains plugins for the Mapsight app: runtime icon styles, document
title, feature deep links, local storage, scroll lock, tracking events, search and geolocation sources, breakpoint
views and mobile view toggling. Take it when you also use the chrome; otherwise list only what you need. Pass
`createDefaultPlugins({olProxy: {dependencies: [...]}})` to extend its `olProxy`.

### Layer and source definitions

`createOlProxyPlugin()` registers a fixed default set (`Map` and `View` are always registered). Everything else exists
in `@mapsight/core/ol-proxy/definitions/<kind>/<Name>` and must be passed explicitly:

| Kind          | Registered by default                                                                                                                                                             | Available                                                                                                                                                                                                                                                                                                                                                       |
| ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `layer`       | `TileLayer`, `VectorLayer`, `VectorOverlayLayer`                                                                                                                                  | `ImageLayer`, `MapboxVectorLayer`, `VectorTileLayer`, `WebGLVectorLayer`                                                                                                                                                                                                                                                                                        |
| `source`      | `OsmSource`, `TileWMSSource`, `VectorSource`, `VectorFeatureSource`                                                                                                               | `XYZSource`, `WMTSSource`, `ImageWMSSource`, `VectorTileSource`, `ClusterSource`, `TileJSONSource`, `BingMapsSource`, `ImageArcGISRestSource`, `TileArcGISRestSource`, `ImageStaticSource`, `ImageCanvasSource`, `ImageMapGuideSource`, `ImageSource`, `RasterSource`, `TileDebugSource`, `TileImageSource`, `TileSource`, `TileUTFGridSource`, `UrlTileSource` |
| `format`      | `GeoJSONFormat`                                                                                                                                                                   | `KMLFormat`, `GPXFormat`, `WKTFormat`, `TopoJSONFormat`, `EsriJSONFormat`, `MVTFormat`, `WFSFormat`, `GMLFormat`, `GML2Format`, `GML3Format`, `IGCFormat`, `OSMXMLFormat`, `PolylineFormat`, `TextFeatureFormat`, `WMSCapabilitiesFormat`, `WMSGetFeatureInfoFormat`, `WMTSCapabilitiesFormat`, `XMLFormat`, `XMLFeatureFormat`                                 |
| `interaction` | `SelectInteraction`, `DragPanInteraction`, `DoubleClickZoomInteraction`, `PinchZoomInteraction`, `MouseWheelZoomInteraction`, `KeyboardPanInteraction`, `KeyboardZoomInteraction` | `DrawInteraction`, `ModifyInteraction`, `SnapInteraction`, `TranslateInteraction`, `ExtentInteraction`, `DragBoxInteraction`, `DragZoomInteraction`, `DragRotateInteraction`, `DragRotateAndZoomInteraction`, `PinchRotateInteraction`, `DragAndDropInteraction`, `PointerInteraction`, `InteractionInteraction`                                                |

Register an XYZ base layer, for example:

```ts
import createOlProxyPlugin from "@mapsight/ui/plugins/common/ol-proxy";

import XYZSource from "@mapsight/core/ol-proxy/definitions/source/XYZSource";

const olProxy = createOlProxyPlugin({dependencies: [XYZSource]});
```

An unregistered type is reported with the same `Dependency unknown/not injected` error. `dependencies` also accepts a
record; its values are registered.

## CSS without the Mapsight stylesheets

`Map` renders a region element `ms3-map-target` and two elements with `ms3-visuallyhidden`: a short text inside the
target ("This part of the page shows a geographical map.") and the keyboard usage list after it. Without the Mapsight
SCSS both texts are visible, the target has no size rule, and it shows no focus indicator. OpenLayers sets the
inline styles of its own `ol-viewport` and `ol-layers` elements itself.

Why each rule is there: the size rule makes the target fill its parent (a parent without height collapses the map to
zero); `position: relative` anchors the focus ring, a positioned pseudo-element (the canvas layers paint above an
outline on the target itself); the background shows until tiles arrive and is read from `--ms3-map-background-color`,
which has no fallback in the Mapsight rule; the focus ring marks the map, which is focusable by default
(`tabindex="0"`); `.ms3-visuallyhidden` keeps both texts available to screen readers.

```css
.ms3-map-target {
	position: relative;
	width: 100%;
	height: 100%;
	background: var(--ms3-map-background-color, #efece5);
}

.ms3-map-target:focus-visible {
	outline: none;
}

.ms3-map-target:focus-visible::before {
	content: "";
	position: absolute;
	inset: 0;
	z-index: 1;
	pointer-events: none;
	outline: 3px solid var(--ms3-focus-ring-color, #005fcc);
	outline-offset: -3px;
	box-shadow: inset 0 0 0 5px #fff;
}

.ms3-visuallyhidden {
	border: 0;
	clip: rect(0 0 0 0);
	height: 1px;
	margin: -1px;
	overflow: hidden;
	padding: 0;
	position: absolute;
	width: 1px;
}
```

Custom properties: `--ms3-map-background-color` (Mapsight default `#efece5`) and `--ms3-focus-ring-color`
(fallback `#005fcc`; the Mapsight tokens do not define it, hosts set it to match their theme).

Also import `ol/ol.css`: the Mapsight stylesheet includes it, and it sets `touch-action` and `user-select` on
`.ol-viewport` and resets its canvases.

With Sass you can reuse the original rules instead of copying them:
`@use "@mapsight/ui/src/scss/blocks/map-target";` and `@use "@mapsight/ui/src/scss/helpers/visually-hidden";`
(or `@include visually-hidden.visually-hidden()` from `mixins/visually-hidden`). The map-target partial also contains
rules for chrome features (drawing crosshair, point-input controls) that stay unused here. The full stylesheet and its
tokens are described in [`@mapsight/ui`](../../packages/ui/README.md#scss-host-builds).

## Layers and sources at runtime

Layers and sources are state, so you add and change them with actions from `@mapsight/core`. Inside `Instance`, get
the store with `useStore()` (or `useDispatch()`):

```ts
import {xhrJson} from "@mapsight/ui/config/feature/sources";
import {interactiveFeatures} from "@mapsight/ui/config/map/layers";

import {mergeConfigAll} from "@mapsight/core/lib/base/actions";
import {setLayerVisibility} from "@mapsight/core/lib/map/actions";

store.dispatch(
	mergeConfigAll({
		featureSources: {
			events: xhrJson("https://example.org/data/events.geojson"),
		},
		map: {
			layers: {
				events: interactiveFeatures(
					"events",
					true,
					{title: "Events"},
					"places",
				),
			},
		},
	}),
);
store.dispatch(setLayerVisibility("map", "events", false));
```

Use `mergeConfigAll` to add layers or sources (merging keeps omitted keys, so it never removes anything),
`setLayerVisibility(controllerName, layerId, visible)` to show or hide a layer, and the actions below to remove them,
seed them with data and wait for their data.

Controller names are the defaults `"map"` and `"featureSources"` (constants in `@mapsight/ui/config/constants/controllers`).

**Removal.** Available from the release that contains `removeLayer`, `removeFeatureSource` and `removeKey`. Remove the
layer first, then its source; both ignore unknown ids. `removeLayer` leaves the feature source and all selections
alone, so clear selections that refer to its features (`deselectAll`) first. Do not use `unset` for this: it keeps the
key with an `undefined` value. See the section on removal in the Action API Decision Guide (`ACTION_GUIDE.md`).

**Initial data.** Available from the release that contains `plain(data)`. `plain()` creates a source without a loader
that your code fills; an empty one ends in the error state `no data` once a layer loads it. Pass initial data to
avoid that, an empty collection is enough:

```ts
import {plain} from "@mapsight/ui/config/feature/sources";

const draft = plain({type: "FeatureCollection", features: []});
```

**Waiting for data.** Available from the release that contains `whenFeatureSourcesSettled`. `dispatch(load(...))`
returns the queued action, not a promise. The helper observes the state instead:

```ts
import {whenFeatureSourcesSettled} from "@mapsight/core/lib/feature-sources/when-settled";

const {status, sources} = await whenFeatureSourcesSettled(
	store,
	"featureSources",
	["places", "events"],
	{timeoutMs: 10_000},
);
// status: "settled" | "timeout" | "aborted"; sources: {places: "ok", events: "error"}
```

Success and failure both settle, so check `sources` before you use the data. A source that is still `idle` (no load
has run yet) is not settled; the wait continues until its load has finished or `timeoutMs` ends it. In React,
`useFeatureSourceLoadState(id)` from `@mapsight/ui/hooks/useFeatureSourceLoadState` returns `missing`, `idle`,
`loading`, `ok` or `error` for one source. See "Waiting for data" in the feature source load lifecycle guide
(`FEATURE_SOURCE_LOAD_LIFECYCLE.md`).

**Feature ids** must be unique across all feature sources of one instance, because selections store only ids and
the lookup returns the first source that contains one. See [Publishing data](PUBLISHING_DATA.md).

## Draw order

Layers are drawn by `options.zIndex`: a higher value is above a lower one, layers without it count as `0`, and layers
with equal `zIndex` keep the order in which they were added. Selection and highlight overlays use `zIndex` `1000`, so
keep your layers below it and set `zIndex` explicitly wherever order matters. Layer groups and the full rules are in
the [Draw order](CONFIG_REFERENCE.md#draw-order) section of the Config reference.

## Base maps

Raster base layers are `TileLayer`s; the helpers in `@mapsight/ui/config/map/layers` build them:

| Base map | Config                                                                                                                                |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| OSM      | `osm(url, visible, metaData)`; the URL is a tile template, see [tile-proxy](TILE_PROXY.md) for a same-origin proxy                    |
| WMS      | `wms(url, params, projection, visible, metaData, opacity)`; `TileWMSSource` is registered by default, see [OGC layers](OGC_LAYERS.md) |
| XYZ      | `{type: "TileLayer", options: {source: {type: "XYZSource", options: {url}}}}` and register `XYZSource` (see above)                    |
| Vector   | `{type: "MapboxVectorLayer", options: {styleUrl}}`; register `MapboxVectorLayer` and install `ol-mapbox-style`                        |

`MapboxVectorLayer` reads a Mapbox or MapLibre style document when the layer first becomes visible. Its `webfonts`
option is described in [Tile proxy](TILE_PROXY.md#vector-styles-and-web-fonts). The full option table and the
`styleTransforms` option, which recolours or hides style layers in the browser, are available from the release that
contains `styleTransforms`: see "Registering `MapboxVectorLayer` and its options" and "Transforming the style in the
browser" in the Tile proxy guide.

```ts
import MapboxVectorLayer from "@mapsight/core/ol-proxy/definitions/layer/MapboxVectorLayer";

const olProxy = createOlProxyPlugin({dependencies: [MapboxVectorLayer]});
```

Mark base layers with `metaData.isBaseLayer: true`. When the visibility of a base layer is set to `true` with a `set`
action, which includes `setLayerVisibility`, every other base layer becomes invisible. So switch base maps by showing
the new one; hiding the current one leaves no base map. The rule applies to such changes only: config that lists
several visible base layers, for example merged with `mergeConfigAll`, is not corrected.

## Reading state

Read state through selectors and hooks only. State paths and fields without a selector are internal and may change
without notice; do not read `state.map.view.center` and similar paths directly. Available from the release that
contains the public read selectors: the supported selectors are listed in the "Reading state" section of the
[Redux architecture](../../packages/core/docs/REDUX_ARCHITECTURE.md) guide.

| Need                   | Use (`@mapsight/ui/hooks/<name>`)                                            |
| ---------------------- | ---------------------------------------------------------------------------- |
| View center, zoom      | `useMapView()` returns `{center, zoom, resolution, rotation}` or `undefined` |
| Zoom and zoom steps    | `useMapZoom()` returns `{zoom, zoomIn, zoomOut}`                             |
| Layer visibility       | `useLayerVisibility(layerId)` returns `[visible, setVisible]`                |
| Attribution strings    | `useVisibleLayerAttributions()`                                              |
| Load state of a source | `useFeatureSourceLoadState(id)`                                              |

The map hooks take the map controller name as optional last argument (default `"map"`). The selection selectors exist
today in `@mapsight/core/lib/feature-selections/selectors`; they take the full state:

```tsx
import {useSelector} from "react-redux";

import {FEATURE_SELECTIONS} from "@mapsight/ui/config/constants/controllers";
import {FEATURE_SELECTION_SELECT} from "@mapsight/ui/config/feature/selections";
import useMapView from "@mapsight/ui/hooks/useMapView";

import {createFeatureSelectionSelector} from "@mapsight/core/lib/feature-selections/selectors";

const selectSelection = createFeatureSelectionSelector(
	FEATURE_SELECTIONS,
	FEATURE_SELECTION_SELECT,
);

export function MapStatus() {
	const view = useMapView();
	const selectedId = useSelector(selectSelection)?.features?.[0];
	return (
		<p>
			Zoom level {view?.zoom ?? "–"}, selected: {selectedId ?? "none"}
		</p>
	);
}
```

To change the selection, dispatch `selectExclusively(FEATURE_SELECTIONS, FEATURE_SELECTION_SELECT, id)` or
`deselectAll(...)` from `@mapsight/core/lib/feature-selections/actions`.

## Controls

**Zoom buttons** with `useMapZoom` (same animated steps as the Mapsight zoom buttons):

```tsx
import useMapZoom from "@mapsight/ui/hooks/useMapZoom";

export function ZoomControls() {
	const {zoomIn, zoomOut} = useMapZoom();
	return (
		<div role="group" aria-label="Zoom">
			<button type="button" onClick={zoomIn} aria-label="Zoom in">
				+
			</button>
			<button type="button" onClick={zoomOut} aria-label="Zoom out">
				−
			</button>
		</div>
	);
}
```

**Attribution** as plain text with `useVisibleLayerAttributions`, which returns the `metaData.attribution` strings of
the rendered layers keyed by layer id:

```tsx
import useVisibleLayerAttributions from "@mapsight/ui/hooks/useVisibleLayerAttributions";

export function Attribution() {
	const texts = Object.values(useVisibleLayerAttributions());
	return texts.length > 0 ? <p>{texts.join(" · ")}</p> : null;
}
```

Keep `attribution` plain text for this (`"© Example contributors"`), as in the config above. Where a link is required,
use the attribution parts selector `visibleLayerAttributionPartsSelector` from `@mapsight/core/lib/map/selectors`,
which returns `{text?, html?}` per visible layer, and render `html` deliberately (see the next section). It is
available from the release that contains `dangerouslySetAttributionHtml`.

**Existing chrome components** can be imported directly (for example `@mapsight/ui/components/map-overlay/zoom-button`
or `.../attribution`) and rendered inside `Instance`, because they read the same store. They bring two requirements:
their strings come from the `lang` plugin's language (German without it), and their markup carries Mapsight class
names (`ms3-*`, or `button button--<action>` for the zoom button by default) that look right only with the Mapsight
SCSS. Without it, prefer the hooks and your own markup.

## Trust boundary

The chrome renders several config and feature fields as HTML (`dangerouslySetInnerHTML`): layer `metaData.attribution`
(unless the future flag `v8_attributionText` is on), `dangerouslySetAttributionHtml`, `legend` and `miniLegend`; the
feature properties `description`, `listInformation`, `tooltip` and `overrideListHtml`; the document that a feature's
`detailsUrl` returns; and the translation string `ui.map.usage.html`. The complete list is in "HTML in config" in the
[Config reference](CONFIG_REFERENCE.md) (available from the release that contains `v8_attributionText`).

A host with its own interface renders those values itself, so the rule is yours to apply: render attribution and
feature properties as text (React escapes them) unless you control the content. Only `Map` renders one of these
fields, the usage text, and it comes from the translation catalog, not from data. The attribution example above
renders text. Use `html` parts only for layer config you author yourself.

## Accessibility

- **Name.** `Map` renders `role="region"` with `aria-roledescription` and `aria-label`. The label is `mapTitle`
  (default: the translation `ui.map.label`); pass `aria-label` or `aria-labelledby` instead to override it.
  Name it for what the map shows ("Places in Example City"), not just "map".
- **Keyboard.** With `enableKeyboardControl` (default), the target has `tabindex="0"` and `aria-describedby` points to
  the visually hidden usage list (`ui.map.usage.html`). The keys it lists (arrows pan, `+` and `-` zoom) come from the
  keyboard interactions that `map()` configures. `enableKeyboardControl={false}` removes the tab stop and the list.
  The list also names `Shift+F10`, which opens the map point menu of the Mapsight chrome (`App`). Your interface has no
  such menu, so replace the string once at startup (for every language you use):

```ts
import {registerTranslations} from "@mapsight/ui/helpers/i18n";

registerTranslations({
	en: {
		"ui.map.usage.html":
			"<dl><dt><kbd>+</kbd></dt><dd>zoom in</dd><dt><kbd>-</kbd></dt><dd>zoom out</dd></dl>",
	},
});
```

- **Focus.** Keep the focus ring from the CSS section; it is the only indicator for the map target.
- **Your controls** need names, focus styles and keyboard operation like any other control. Do not rely on the canvas
  for information; list the features in your own markup as well.

The overall status and open items are in [Accessibility](../ACCESSIBILITY.md).

## Keeping the view in the address

Available from the release that contains the view permalink plugin. The opt-in plugin
`@mapsight/ui/plugins/browser/view-permalink` writes the map view and the visibility of switchable layers into the page
address (`#map=zoom/lat/lon&layers=id,id`) and restores them on load. Add it to `createOptions.plugins`, and call the
`destroy()` method of the plugin object when the instance goes away. See the view permalink plugin guide
(`VIEW_PERMALINK.md` in `packages/ui/docs`) for options and limitations.
