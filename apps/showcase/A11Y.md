# Showcase accessibility regression gate

Build from the workspace root, then run the same check used by CI:

```sh
pnpm turbo run build --filter=@mapsight/showcase --filter=@mapsight/a11y-audit
pnpm exec playwright install chromium
pnpm --filter @mapsight/showcase test:a11y
```

Playwright starts and stops a local static showcase on port 5174. The audit CLI
runs desktop, mobile and 320 px reflow checks, including keyboard selection and
closing details. Reports and screenshots are written to `apps/showcase/a11y-report/`
and uploaded as the `showcase-accessibility` CI artifact (14-day retention).

The gate rejects new **moderate/serious/critical** failures relative to `a11y-baseline.json`.
It also rejects execution errors regardless of severity, including page/scenario
load failures. Informational notes (such as walking within an open modal) are
reported separately. No manual tests are marked as passed by this gate.

## Baseline maintenance

The baseline retains `startedAt` and failed `findings` from a complete report,
which are the fields used for fingerprint comparison. Needs-review entries are
not accepted failures: if a later run classifies them as failures, the gate must
check them as new. It records accepted regression debt,
not conformance. Review the full generated report, including moderate/minor
findings and needs-review results, before updating it. Never refresh a baseline
just to make a failing CI check green. A clean run must exercise all configured
states and have no execution errors.

The 28 October baseline is from current main plus the closeout fixes, including
#400/#401. The pre-fix report and local host harness evidence are retained in the
implementation worktree's `.scratch/status-closeout/`; host verification uses
UI 7.8.0 on `a0f9c8d`, not unpublished closeout packages.

The follow-up run covered all 12 states with no execution errors or failed
findings. The baseline is now empty; 19 needs-review findings remain. The three
mobile hidden-focus findings in the earlier run were audit overflow-clipping
false positives for viewport-fixed chrome; the new close-details scenario also
caught a real collapsed-panel focus stop, now fixed by making its shell inert.

The count-aggregator showcase configures `sectionHeadingAs: "h2"` below the page
heading. Hosts can choose their own section heading level; the package retains
`h4` as its default. Contrast over rendered map tiles, screen-reader output, host
content, reduced motion and point-input forms require further checks beyond this
baseline.

The `ui-point-input` target (`/ui/point-input`) adds five states: initial
desktop/mobile/reflow plus focusing the map, panning and confirming with Enter on
desktop and mobile. That scenario expects the confirmation announcement and focus
to stay on the map. Its first local run had no failures and 4 needs-review
findings: map attribution contrast over tiles, and label-in-name for the symbolic
"?" keyboard-help button.
